# Журнал решений

Формат: решение — причина. Отвергнутое тоже фиксируем, чтобы не предлагать повторно.

## Принятые решения

### Движок
- **Godot 4.** Бесплатный, лёгкий, хорош для 2D, ИИ хорошо знает GDScript. Source отвергнут: устарел, заточен под шутеры, Source 2 недоступен инди.

### Код и архитектура (подробно — DEVELOPMENT.md)
- **Godot 4.7.x, только GDScript.** C# не используем: проще, без фризов сборщика мусора.
- **Симуляция отдельно от отображения.** Логика — чистые классы без нод; ноды только рисуют и передают ввод. Причина: тесты, реплеи, боты, будущий сетевой режим.
- **Детерминированная симуляция:** фиксированный тик, только целые числа, свой RNG с сидом матча. Причина: мультиплеер через передачу команд, а не состояния.
- **Ввод игрока — команды** (паттерн Command).
- **Статы — в ресурсах `.tres`**, синергии — через теги.
- **Тесты — GUT 9.x.**

### Жанр и ядро
- **Соревновательный TD с отправкой мобов сопернику** (как Legion TD 2 / Bloons TD Battles 2). Отправки растят доход. Причина: соревновательность с людьми + проверенная основа жанра.
- **Сетка-«рюкзак» на поле (фишка А):** башни-фигуры, бонусы за соседство. Главное отличие от конкурентов.
- **Лобби 5 игроков, каждый сам за себя (фишка В в изменённом виде).**
- **Фиксированный путь, одинаковый у всех.** Проще в разработке, честнее, лучше сочетается с сеткой. Лабиринт отвергнут.
- **Мало места для башен — намеренно** (идея автора): старые башни приходится продавать.
- **Путь и сетка растут с уровнем магазина** (идея автора): площадка одного размера, меняется форма пути — прямой → Г → П → … Новые участки пути открывают новые клетки. Причина: без игры с масштабом, ограниченное место, уровень магазина — общее вложение.

### Экран и управление
- **Один экран без камеры, разделённый на две половины** (идея автора): в подготовке — меню + своё поле, в волне — поле соперника + своё поле. Верх/низ или лево/право — выбрать в прототипе.
- **Сейчас ПК, но с расчётом на смартфон в будущем:** масштаб и вёрстка под маленький экран, управление только мышью / одним пальцем (нажатия и перетаскивание).

### Структура матча
- **Каждый раунд — дуэль 1 на 1** (пары — соперники, не команды). Причина: новичку легко готовиться к одному сопернику.
- **Призрак** при нечётном числе игроков (как в Полях сражений).
- **HP героя + рост урона прорывов** (×2 с 10-го, ×3 с 15-го раунда) — чтобы матч длился 15–20 мин.
- **Итог — места 1–5**, рейтинг от места.
- **Базовая волна + отправки соперника** — раунд никогда не пустой.

### Осада лидера
- **Раз в 5 раундов двое самых слабых атакуют лидера** (идея автора). Объявляется за раунд до.
- **Отправки лидера в осаде: каждый атакующий получает полную копию** (вариант 3). Причина: симметрия, полное соло, нет нового кода.
- **Награды атакующих индивидуальные** (за урон своих мобов + бонус за прорыв порога) — без зависимости от «напарника».

### Герои
- **Выбор из 3 случайных, пассивка + активка** (как в Полях сражений). Список — черновик.

### Экономика (подробно — docs/02_economy.md)
- **Один ресурс — золото.** Новичку проще, глубина — в решениях, а не в счётчиках. Второй ресурс — только если в прототипе не хватит глубины.
- **Золото = доход + награда за убийства.** Слабая отправка против сильной обороны кормит соперника — это тоже решение.
- **Отправка навсегда растит доход** (как в Legion TD 2), независимо от прорыва. Окупаемость ~5 раундов → к концу матча вложения в доход сами перестают окупаться.
- **Улучшение башен — слияние двух одинаковых** (выбор автора) в башню уровнем выше, до 3-го уровня. Фигура не меняется, клетки второй башни освобождаются.
- **Уровень магазина (1–4) покупается за золото** (выбор автора); цена падает на 1 каждый раунд без повышения. Тир башни = уровень магазина.
- **Продажа:** 100% в ту же фазу подготовки, потом **треть** вложенного (автор: половина — слишком щедро).
- **Витрина: 3 предложения + 1 за каждый уровень магазина** (автор: 5 — слишком много для старта).
- **Все башни стоят одинаково — 6 золота** (пока предположение). Тир влияет на силу, не на цену.
- **Игрок покупает только башни; атакует скиллом отправки героя** (идея автора). Скилл применяется за золото **не больше 1 раза за раунд**, цена **растёт с каждым раундом**; отправлять каждый раунд можно только при сильной экономии. Каждое применение навсегда +доход. Формулу цены автор продумает сам. У каждого героя свой скилл — детали на этапе контента; в прототипе один общий.
- **Бафы отправки** (идея автора): после каждой битвы выбор 1 из 3 случайных бафов для своих юнитов; действуют весь матч и складываются; уровень магазина повышает шанс сильных бафов. Новые типы юнитов в пачке — через бафы (вместо открытия мобов по раундам).
- **Денежного камбека кроме осады нет.** Добавим, если будет снежный ком.
- **Алхимик** получил новую пассивку: сливает разные башни одной школы и уровня (старая — слияние одинаковых — стала общим правилом).

### Сеттинг (направление, детали — на этапе лора)
- **Славянская тематика** (выбор автора): славянская и древнерусская мифология — Перун, лешие, кикиморы и т. п., с элементами современной культуры. Визуал и лор обсудим позже.
- **В коде и данных прототипа — нейтральные имена по функции** (`fast_mob`, `fire_tower`), без чужих фэнтези-штампов (орки, гоблины). Тематические имена — позже, в отображаемых названиях.

### Процесс
- Прототип на «квадратиках» против ботов — **до** лора и графики.
- **Прототип начинаем сразу после экономики** (решение автора, 2026-10-29), контент — минимальные заглушки, прорабатываем по ходу.
- Сеть — после проверки ядра.

## Отвергнутые идеи (не предлагать без новой причины)
- **Автобатлер с лобби (как Поля сражений)** — слишком похоже на Поля сражений, «скука».
- **Карточный рогалик с автобоем** — тоже по сути Поля сражений.
- **Рогалик «рюкзак + Brotato»** как отдельная игра — ниша занята (God of Weapons, Backpack Battles), а без PvP — просто рогалик. Сетку взяли в TD.
- **3D рогалик как Risk of Rain** — слишком сложно для первой игры; рогалики против ботов не цепляют автора.
- **Обязательные команды / зависимость от напарника** — игра для соло-игроков. Командный режим — только опция в будущем.
- **Свободный выбор цели для отправок** — перегрузка для новичка, кингмейкинг, затягивание.
- **Объединение полей двух слабых в осаде (мобы лидера проходят оба поля)** — создаёт зависимость от напарника и сложнее технически. Возможно — для будущего командного режима.
- **Лидер в осаде только обороняется** — лидеру скучно, слабым «халявный» раунд.
- **Мобы-воры (фишка Б: прорвавшиеся уносят золото)** — не выбрана на текущем этапе (можно вернуться как к типу моба/герою).
- **Лабиринт вместо фиксированного пути** — сложнее в коде и для новичка.
- **Проценты за накопленное золото (как в Auto Chess)** — третья ось решений, тяжело новичку.
- **Доход от отправки только при прорыве** — экономика зависит от обороны соперника, можно застрять.
- **Улучшение башен за золото (уровни) / только новые покупки** — выбрано слияние.
- **Фигура растёт при слиянии** — улучшенная башня может не влезть, нужно по 3 формы на башню.
- **Золото за потерянное HP** — можно специально пропускать мобов.
- **Покупка разных мобов для отправки из общего списка, открытие по раундам** — заменено скиллом отправки героя + бафами.
- **Бафы отправки на один раунд** — ничего не накапливается; выбрали бафы на весь матч.
- **Скилл отправки сколько угодно раз за раунд** — автор решил: один раз за раунд, с ростом цены.
