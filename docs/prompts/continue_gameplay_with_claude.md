## Выбранное направление

Армия создаёт ситуацию, особый приём героя позволяет её использовать.
В бою два важных решения: когда выпустить подкрепление и когда применить героя.
Приём героя занимает место общего обряда. Дополнительная колода или валюта не нужны.
Строительство, автоматическая стрельба, реакции стихий и сила сборки остаются важны.
Игрок должен понимать свою хитрость, ответ соперника и причину результата.

Уже сделан отдельный прототип «Дуэль волхвов» из главного меню:
- Основной отряд выходит сам, подкрепление — по одному приказу или автоматически
  до срока. Можно выбрать быстрых разведчиков или крепких латников.
- Яга переносит одну башню на подготовленную вторую позицию; в пути та не стреляет.
- Горыныч после видимого предупреждения временно подавляет выбранную зону обороны.
- Есть противник-бот, обычная скорость, пауза, повтор того же сида и другой план.
Точные числа — data/siege_trial.tres. Основной матч ещё не переведён на эти правила.

Код: src/sim/siege_trial*.gd, src/sim/data/siege_trial_config.gd,
src/ui/siege_trial_panel.gd, src/view/siege_field_view.gd.
Сцена: scenes/siege_trial.tscn. Проверки: test_siege_trial.gd,
tools/siege_trial_smoke.gd. Последняя прежняя полная проверка: 355/355 GUT;
это исторический результат, новые совместные изменения требуют своей проверки.

## Как развивать

1. Быстро оцени актуальный опыт: есть ли значимый выбор времени, понятна ли цель,
   можно ли ответить на приём, хочется ли повторить бой. Сначала исправь мешающий баг.
2. Выбери ближайшее небольшое улучшение и кратко объясни ожидаемый эффект для игрока.
   Реализуй и проверь его; не заканчивай сессию одним списком идей.
3. Кандидаты: более осмысленный состав/порядок отрядов, понятные признаки намерения
   соперника, возможность выманить приём, более выразительная подготовка героя,
   следующий герой с другим правилом (например, обмен башен Домового).
   Это варианты для выбора по текущим проблемам, не обязательный список внедрения.
4. Прежде добавления кнопок ищи глубину в существующих двух приказах. У приёма
   должны быть удачный момент, цена ошибки и ответ противника. Бот не должен
   читать будущие команды человека. Отдельно проверь незаметное наращивание сложности.
5. Перенос покупок/развития и затем осад/призраков в новую модель выполняй постепенно,
   когда короткий бой уже работает. Не смешивай все эти задачи с одним изменением.
   Сохранение текущего обычного режима позволяет сравнивать варианты.

Автор разрешает инициативу внутри этого направления. Не требуется согласовывать
каждый коэффициент или небольшой обратимый опыт. Масштабную смену концепции
не считать принятой автоматически. Новые правила и результаты фиксируй кратко.

## Проверки и экономия контекста

Симуляция без нод, целые числа, фиксированные тики, сид RNG, ввод командами.
Для логики — осмысленные GUT и детерминизм; для управления — smoke, для картинки —
реальный запуск по возможности. Не выдавай headless-проверку за осмотр рендера.
Перед Godot задавай XDG_CONFIG_HOME="$PWD/.godot/local-config"
и XDG_DATA_HOME="$PWD/.godot/local-data". Итоговая проверка: python3 -I tools/check_project.py.
Сеть/пакеты/домашние конфиги — по согласованию, доступ по умолчанию только проект/Godot.

в локальный лог с кратким итогом, подробности только при ошибке. Не перечитывай
неизменившиеся инструкции, не проводи новый полный аудит и не пиши большие отчёты.
