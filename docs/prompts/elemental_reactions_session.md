## Согласованный дизайн — не менять без веской причины

### Пантеон: 7 богов

| # | Бог | Стихия / статус | Что даёт в одиночку |
|---|---|---|---|
| 1 | Сварог | Огонь → **Горение** | периодический урон |
| 2 | Перун | Молния → **Заряд** | шанс цепи 20% |
| 3 | Вода | Вода → **Мокрота** | только статус, сама без урона |
| 4 | Стрибог | Ветер → **поле/геометрия** (не статус) | разгоняет/тормозит мобов |
| 5 | Лёд (имя позже) | Холод → **Заморозка** | замедление |
| 6 | Чернобог | Проклятие → **Проклятие** | отложенный взрыв урона |
| 7 | Бог войны (имя позже) | чистая физика, без статуса | ракеты/механизмы, сильный прямой урон |

Каждый бог — 3 башни с разными ролями (зачинщик статуса / усилитель / финишер), а не просто
«маленькая и большая». Это и есть «1–2 крутые стратегии на фракцию».

### Реакции (направленные: «цель со статусом X получает удар стихией Y»)

| Статус на цели | Бьёт | Реакция | Эффект |
|---|---|---|---|
| Мокрота | Молния | **Цепь** | отскок до 100%, +немного урона *(уже есть)* |
| Мокрота | Огонь | **Пар** | урон ×1.25 + **тушение**: снимает мокроту и горение |
| Мокрота | Лёд | **Заморозка** | цель застывает на N сек |
| Мокрота | Проклятие | **Зараза** | проклятие при взрыве перескакивает на соседнего мокрого |
| Мокрота | Ветер | **Разгон** | толчок вперёд + мокрота переходит на соседей |
| Горение | Молния | **Прожарка** | мгновенный урон + **микро-стан** ~0.2 с |
| Горение | Лёд | **Таяние** | урон ×1.5, снимает лёд, **без нового горения** |
| Горение | Ветер | **Пылающий ветер** | постоянный урон, пока цель под ветром, + разнос по области |
| Холод / Заморозка | Ветер | **Стужа** | разнос холода по области + замедление |
| Проклятие | Лёд | **Консервация** | лёд «замораживает» проклятие: продлевает задержку, но усиливает итоговый урон |
| Заморозка | физ (Бог войны) | **Раскол** | оглушение + дополнительный урон |
| 2 статуса на цели | физ (Бог войны) | **Добивание** | дополнительный физ-урон по «ослабленной реакцией» цели |
| Заряд | Лёд | **—** | нет реакции: статусы сосуществуют |

Три «огненные» реакции разведены по смыслу: **Пар = контроль** (тушение), **Таяние = чистый
большой урон**, **Прожарка = взрыв + микростан**.

### Правила системы

- **Реакция усиливает, а не обязательна.** Новичок играет одним богом и проходит; опытный
  читает 4 богов матча и собирает пару с сильной реакцией.
- **Максимум 2 статуса на мобе.** Реакции поглощают статусы — комбинаторика не взрывается.
- **Не копировать Геншин.** Ветер — поле/геометрия, а не стихия с уроном; реакции
  направленные; Бог войны — отдельная «физическая» фракция, которая добивает помеченных.
- **Детерминизм обязателен:** статусы и реакции — целые числа, тики, RNG симуляции с сидом,
  хэш состояния включает статусы. Никаких `randf()`, `Time`, float в sim.

### Идолы — остаются

Идолы усиливают выбранного бога: тир его башен, урон его башен, дополнительные цели для его
башен и т.п. Три основы, развитие заговорами из лавки, без слияния копий идолов.

### Драфт 4 из 7

- В начале матча для всех игроков выпадают **4 случайных бога из 7** (общий пул, как племена
  в «Полях сражений»). Остальные 3 в этом матче не участвуют: их башни и заговоры не
  появляются в лавке.
- Драфт тянется из RNG матча с сидом → детерминирован и тестируется.
- Игрок видит 4 богов **до выбора героя** и решает, какую пару собирать. Герой с аффинити к
  стихии даёт старт (например, водный герой дешевле ставит воду или начинает с желобом).
- **Жёсткое требование:** реакция-граф + Бог войны должны гарантировать рабочую синергию при
  **любой** четвёрке из 7. Добавь проверку/тест, что любой драфт даёт хотя бы один жизнеспособный
  билд, и что «мёртвые» пары оживают через физ-добивание Бога войны.

## Порядок работ — по приоритету

1. **Ядро реакций.** Статусы на мобе + детерминированный резолвер реакций + тесты. Сначала
   прогнать на уже существующих огне/воде/молнии/ветре, не ломая их.
2. **Лёд** (5-й бог): холод → заморозка, стужа, раскол, консервация проклятия.
3. **Бог войны** (физика): ракеты/механизмы, добивание по 2 статусам, раскол замороженных.
4. **Чернобог** (проклятие): отложенный взрыв, зараза, консервация.
5. **Драфт 4 из 7** + фильтр лавки по активным богам + герои-аффинити.
6. **Идолы** под новых богов (тир/урон/доп. цели).
7. *(Опционально, если останется бюджет)* **Привязка башен вместо тетриса**: башня цепляется
   к одной другой и делает реакцию гарантированной (например, Вода → Перун = всегда цепь 100%).
   Не трогать тетрис, пока ядро реакций не готово.
8. *(Только если останется бюджет)* **Юниты с резистами**: теги `resist`/`weak` в данных мобов.
9. **Баланс и читаемость**: сравнение на одинаковых сидах ботов, компактная таблица реакций в
   UI по ховеру, подсказки «почему сработала реакция».

На 5 часов реалистичный минимум — пункты **1–5**. Пункты 7–8 — не в ущерб надёжности ядра.

## Технические требования

- Симуляция отдельно от графики, без нод; статусы и реакции — данные (`ReactionData` в
  `data/`), а не захардкоженные ветки по имени башни. Связи — через теги (`&"fire"`, `&"water"`,
  `&"ice"`, `&"curse"`, `&"physical"`, `&"heavy"`).
- Резолвер реакций — чистая детерминированная функция: `(входящая стихия, статусы цели) → эффект`.
  Юнит-тесты на каждую реакцию и на крайние случаи (смерть при реакции, 2 статуса, щит).
- Баг логики — сначала воспроизводящий тест, потом исправление.
- Новый контент — ресурсы `.tres` + запись в активный `data/game_config.tres`; наличие файла в
  папке не означает активность.
- Всё по `DEVELOPMENT.md`: статическая типизация, Godot 4 синтаксис, целые числа, детерминизм.
