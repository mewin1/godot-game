# 33 — План оптимизации под телефон (9 ноября 2026)

Статус: план. Шаги 0 и 1 сделаны, остальное — предложение, ждёт выбора автора.
Замеры — «Обряд», день с боем, 2560×1440, RTX 5070, время кадра видеокарты (ГП).
Замер: части сцены выключались по одной, ГП-время — `RenderingServer.viewport_get_measured_render_time_gpu`.

Видеопамять: ~670 МБ на кадр 2560×1440. Из них текстуры материалов 3D — 42 МБ (было 86 МБ),
остальное — буферы экрана (TAA, MSAA, SSAO, тени 4096², дымка) и интерфейс.
На телефоне 2400×1080 × 0,75 буферы будут в 3–4 раза меньше.

## Сделано
0. **8 ноября:** лес по участкам 16 м, факелы без теней леса, TAA + MSAA 2x, профиль `RenderQuality`
   (`-- --quality=mobile`: 75 % разрешения + FXAA, без теней леса/факелов, SSAO, дымки, DOF; частиц вдвое
   меньше; 30 FPS) — ГП 5 мс в 2560×1440.
1. **9 ноября: сжатие текстур.** Камни (6), лесная земля (9, нормали — BC5), мостовая и ручей (4) были
   несжатыми (RGB8, по 4 МБ на 1024²). Теперь VRAM-сжатие: 86 → 42 МБ, на глаз без разницы.
   Сжатие существ (ворона, медвежонок) автор включил сам — те же настройки.

## Предлагается (по порядку выгоды)

2. **Проверить облик на рендере телефона.** Для телефона в project.godot выбран Compatibility (OpenGL ES 3):
   там нет TAA, SSAO, объёмной дымки, мягких теней; свечение проще. Запустить на ПК с
   `--rendering-method gl_compatibility --quality=mobile`, снять день/ночь, решить, что подменить
   (дымка у земли уже есть — `_build_ground_mist`). Альтернатива — рендер Mobile (Vulkan): ближе к ПК,
   но не идёт на старых телефонах. *Решение автора: Compatibility (шире охват) или Mobile (красивее).*
3. **Форматы текстур для Android:** включить `rendering/textures/vram_compression/import_etc2_astc`
   (без него экспорт на Android не соберётся). Кэш импорта вырастет (второй формат).
   Тогда же — `process/size_limit=1024` для текстур 2048² (Илья, терем, факелы, медвежонок): в кадре они
   мелкие, разница не видна, память ×4 меньше.
4. **Ели проще.** Ель 4264 треугольника — для телефона много. Сделать в Blender облегчённую ель (~1000)
   для профиля MOBILE, а на ПК оставить нынешнюю. Альтернатива — рисованные ели-картинки (`bb/`, уже
   есть в PvP) для дальних рядов. Выгода на телефоне — самая большая из геометрии.
5. **Трава реже на телефоне:** в профиле MOBILE оставлять каждый второй пучок вне двора (у частокола —
   все). Минус ~1 млн треугольников. Облик: луг чуть реже.
6. **Тени на телефоне:** `directional_shadow/size.mobile` 2048, `positional_shadow/atlas_size.mobile` 1024,
   мягкость теней — низкая (настройки проекта с суффиксом `.mobile`, на ПК не меняются).
7. **Ограничение кадров:** телефон — 30 FPS (уже в профиле), ПК — вертикальная синхронизация (как сейчас).
   При желании — 60 FPS на мощных телефонах переключателем в настройках.
8. **Замер на настоящем телефоне:** экспорт Android, удалённая отладка Godot, монитор
   Performance (FPS, ГП, видеопамять, треугольники). Целевой ориентир — средний телефон 2022 года
   (Adreno 610–650 / Mali-G57): 30 FPS ровно.
9. **Интерфейс:** листы `assets/dusk/*.png` (7 по ~6 МБ без сжатия) — на видеопамять почти не влияют,
   но раздувают сборку; сжать WebP без потерь при экспорте — по необходимости.

## Чего не делать
- Не выключать MSAA на ПК: хвоя становится пятнами (alpha-to-coverage работает только с MSAA).
- Не возвращать одну MultiMesh на весь лес: её нельзя отсечь, а факелы перерисовывают весь лес.
