# AGENTS.md — инструкции для Codex

Действует для всего проекта. Общаемся по-русски, коротко и понятно: автор — один
разработчик, новичок в геймдеве. Godot 4.7.x, GDScript, GUT 9.7.1.
Игра «Застава» — соревновательный tower defense: 5 соло-игроков, дуэли и осады лидера.

## Чтение по задаче

- Для работы над игрой в начале сессии прочитай `memory/CURRENT.md` и проверь
  `git status --short`. Для общих вопросов без работы с проектом файлы не нужны.
- Перед написанием, правкой или ревью кода прочитай в `DEVELOPMENT.md` блок «Всегда»
  и нужные разделы по «Оглавлению», не весь файл. В пределах контекста повторно не
  читать неизменившиеся инструкции.
- Найти реализацию и проверки → нужная часть `memory/PROJECT_MAP.md`, затем конкретные
  файлы. Механики, баланс, контент и игровое управление → соответствующие разделы
  `docs/CURRENT_RULES.md`; числа сверяй с активными `.tres` в `data/game_config.tres`.
- Новые механики → `docs/00_pitch.md` и связанные решения в `decisions.md`, включая
  отвергнутые идеи. Визуал/раскладка → `docs/06_visual_style.md`, `docs/14_ui_fix_notes.md`.
- Остальные документы находи через `docs/README.md`; решения, вопросы и термины —
  в `decisions.md`, `open_questions.md`, `glossary.md` по теме через `rg`.
  Историю и журналы читай только при необходимости, не все документы подряд.
- Различай реализованное, проверенное автором и предложенное. Позднее решение
  заменяет раннее; при расхождении с кодом сначала проверь поведение.

## Обязательные правила

- Симуляция `src/sim/` отдельно от графики: без нод, целые числа, фиксированный тик,
  свой RNG с сидом; ввод через команды. Правила не переносить в UI, числа — в ресурсы.
- Один экран без прокрутки: лавка/армия слева, карта справа, идолы под ней, резерв снизу.
  ПКМ поворачивает; сброс на лавку продаёт; заговор прямо на цель; подарок сразу в слияние.
- Путь и место растут только от магазина; ограниченность места и резерв намеренны.
  Три пустые основы идолов развиваются заговорами без слияния копий. Попутный ветер
  ускоряет. Обычные армии — люди, сказочные существа — герои/персонажи.
- Перед заметной задачей — короткий план; затем небольшие проверяемые изменения.
  Выполняй запрос до проверяемого результата, без новых механик и массовых переделок
  вне задачи. Чужие незакоммиченные изменения сохраняй, не откатывай.
- Баг сначала воспроизведи тестом. Логику симуляции проверяй GUT и детерминизмом;
  визуал — запуском; баланс — сравнением логов и живой игрой, боты лишь ориентир.
  В отчёте отделяй выполненные проверки от необходимых, но не выполненных.
- Обновляй только затронутую документацию: правила, решения и вопросы — по существу;
  точку продолжения — `memory/CURRENT.md`, историю — `memory/sessions/`.
  Текущий этап хранится в памяти, здесь не дублируется. После сжатия продолжай по памяти
  и Git, не начинай выполненную работу заново. Предложение не считать принятым без автора.
- **Доступ: только проект и Godot.** Вне проекта (конфиги, сеть, пакеты, домашний каталог)
  ничего не смотреть/менять без согласования. Зависимости и внешние сервисы — по согласованию.
  Коммиты без строки соавторства ИИ; логи и `.godot/` в Git не добавлять.

## Запуск и проверки

Перед командами Godot задавай
`XDG_CONFIG_HOME="$PWD/.godot/local-config" XDG_DATA_HOME="$PWD/.godot/local-data"`.

- Игра: `godot --path .` или F5.
- GUT: `godot --headless --path . -s res://addons/gut/gut_cmdln.gd -gexit`
- Полная проверка: `python3 -I tools/check_project.py`.
- Боты, анализ и специальные проверки — команды в `memory/PROJECT_MAP.md` по задаче.
